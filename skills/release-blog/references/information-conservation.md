# 重写既有稿：信息守恒（2026-09-09）

对已发布的稿子做减法改写时，删掉的内容必须逐条对账。起因是一次真丢失：
保留了「（release commit 原话）」这个归因，却删了原文开头的 commit 链接，
留下一个悬空引用。

工具：`node scripts/audit-blog-deletions.mjs`（对比 HEAD 与工作区；
新增文件会报 0 删除，属正常）。它给的是待办清单不是判决——
每条都要人工归到「刻意删」或「误报」。

- **引文留着，链接就得留着。** 任何「某某原话」「release commit 说」的
  归因必须带可点永链。信息守恒优先于精简。
- **真删除 ≠ diff 的删除行。** 改写过的行会同时出现在 `-` 与 `+` 两侧。
  判据：删掉的行若在新稿里找不到对位（字符 bigram Jaccard ≥ 0.3）才算丢
  失；frontmatter 行不计入。
- **丢失锚点单独扫。** URL / 行内 `` `…` `` / 版本号，出现在旧稿而不在新
  稿里的，逐个判定「刻意删」还是「误删」。三类常见误报：内容挪进了代码
  块（行内反引号正则抓不到）、反引号被拆开（`uvx/pipx run` → 两个）、
  措辞改写（`@latest` → `name@version`）。
- **站内链接单独验。** 正文的站内链接要在 `dist/` 里逐个确认能解析，且不
  出现跨语种泄漏（en 稿链到 zh-only 路径；镜像行除外）。

## 门禁脚本本身的失效风险

`scripts/audit-blog-links.mjs` 的判定细节（改脚本前先读这一段）：

- **按行判定，不按 href**：同一个 href 出现在镜像行上被豁免，不代表它出现
  在正文行里也合法。
- **镜像行 = 以 `- ` 开头、且只含一个链接的列表项**。多链接的「本站系列」
  行不算镜像行，不享受豁免。
- **图片是资源不是页**（2026-09-11）：`![alt](/blog-assets/…)` 没有尾斜杠、
  没有语种，走 `ASSET_RE` 分支（png/jpg/jpeg/webp/svg/gif/avif/ico/pdf/
  mp4/webm），跳过尾斜杠与跨语种判定，改判 `dist/<path>` 是否存在。
- **改完必须造双向反例**：见 SKILL.md 的 Verification 两条。
