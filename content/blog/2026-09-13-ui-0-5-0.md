jixoai-ui v0.5.0 is out (2026-09-13). 36 commits — 5 feat, 13 fix, 13 docs by prefix, the rest test, chore, and merges — with a single-thread mainline: spin. The loading indicator is now a name — `<Spin spinner="dots">` or `<Spin spinner="blocks-wave">` — not a cursor parameter. The same line carries the vite-plugin spinners feature, the icon baseline debt cleared, and three playground controls standardized. No breaking changes; upgrading is zero-migration.

## spin: a name, not a cursor

The ora ruling landed first: plain text, no `[` `]` wrapping. Then the name channel itself — one `spinner` prop, two resolution lanes, **the generated svg artifact first, the text catalog second**:

```svelte
<!-- svg lane: compile-time artifact names, blocks-wave the default -->
<Spin spinner="blocks-wave" />

<!-- text lane: one of the 59-name cli-spinners catalog, frames verbatim -->
<Spin spinner="dots" />
```

Names are a compile-time union — a typo fails type checking, and at runtime only a cached-once warning remains. Sizing invents no units of its own: the text lane rides the density ruler's `var(--jx-text)`, the svg lane `var(--jx-icon)` — the same ruler the jixoai.com site typography rides. A spinner inside body text is body-sized; a loader in an icon slot is icon-sized.

```spin
{"demos":[{"spinner":"dots"},{"spinner":"arc"},{"spinner":"line"},{"spinner":"blocks-wave"},{"spinner":"tail-spin"}],"caption":"two lanes, one prop — dots / arc / line are text-catalog names, blocks-wave / tail-spin svg artifact names; this row is the live component turning in the page, not a screenshot"}
```

Accessibility is the foundation, not a patch: `role="status"` (carrying the implicit aria-live waiting semantics), the `aria-busy` wrapping posture, and a one-line `prefers-reduced-motion` kill to a static frame. None of it costs the caller a single line.

## The text lane: a flat CSS-animation engine

The engine's shape is one technical ruling: **all frames rendered flat, once; JS only fills animation parameters**. Every frame lives in the DOM (a one-cell grid + `white-space: pre`, zero layout jitter) and CSS animation lights the frame whose turn it is — one injected `@keyframes` rule per parameter set, one negative `animation-delay` per frame phasing it into its slot.

The payoff is structural: no element churn (frame switches cause zero DOM mutations; GC and style recalculation stay quiet), no JS clock (main-thread jank never touches the beat — the compositor keeps time), and DevTools' Animations panel can scrub the cycle frame by frame — you can literally see each frame's slot and its linger interval on the timeline. Reduced motion is a static media kill, not a runtime branch.

## The trail: lingerType and hand-tuned pairs

The ghost trail was renamed to something more honest — linger: the previous frame stays alive a while longer as a linear fade. `linger` counts milliseconds, `'auto'` defers to the catalog. The fade's shape is `lingerType`:

- `end` (default) — hold the full beat, then a linear fade-out;
- `start` — the fade-in **completes before the handoff boundary**, so the next frame is already in place as it takes over (pre-boundary entry, not boundary-start);
- `both` — fade in and fade out on both ends.

`'auto'` is not computed by formula; it is hand-tuned per name: every catalog entry carries its interval/linger pair in the curator script — dots 80/160, dots2 120/0, pipe 120/120, line 160/0, simpleDots 160/160 (with the `·` glyph) — and the engine faithfully turns those pairs into keyframe percentage stops.

```spin
{"demos":[{"spinner":"dots","interval":160,"linger":0},{"spinner":"dots","interval":160,"linger":160},{"spinner":"dots","interval":160,"linger":480},{"spinner":"growVertical"}],"caption":"the trail is a real animation: the same dots under linger 0 / 160 / 480, and growVertical's hand-tuned pair (120/120)"}
```

Two traps worth recording from the polish rounds: **same-percentage stops merge** (`10%{opacity:1}10%{opacity:0}` — CSS lets the latter swallow the former, turning the whole window into a linear fade; a discrete hide must ride `steps(1,start)`) and **the solid-frame law** (when linger ≥ interval the entry length caps at interval/2, or opacity peaks for a single instant).

```

## The svg lane: SMIL and three Chrome defects

The svg lane runs the artwork's own SMIL; the component owns exactly three things: **per-instance id namespacing** (place the same loader twice and its `begin="x.end"`-style syncbase references never cross-resolve), **a `{#key}` full rebuild on switch** (swapping innerHTML ammunition inside a persistent svg activates the animation in Chrome 1 times out of 12), and **dynamic-insertion activation kicks** (stylesheet text reprocessing + `setCurrentTime(0)`, firing only when `document.readyState === 'complete'` so hydration never slaps a running loader back to its start).

The lane was measured into existence: all 94 magecdn loaders walked the component path under pixel verification (83 green outright, 11 rescued by the kicks), with 15 context-dependent dynamic loaders excluded with receipts. Colors normalize to `currentColor` — loaders follow the text color, both themes served; the demos on this page are the live proof — flip the site theme and watch the same loaders re-dress.

```

## vite-plugin: the spinners feature

The spinners feature in `@jixoai/ui-vite-plugin` 0.4.0 mirrors the icon library law for law: `jixoai({ spinners })` is **off by default** — no feature option, no codegen; sources are `inline` or `{ file }` references; the RAW safety gate still turns untrusted shapes away; the artifact has a single writer (`gen:spins` generates, `verify:spins` gates — a hand-edit goes red in CI).

One deliberate non-feature: **no svgo**. `convertShapeToPath` rewrites `<circle>` into `<path>`, and SMIL `<animate>` targets elements by shape type — one optimizer pass and the animation targets are gone. Loader svgs pass through under RAW semantics, with only an explicit normalization checklist applied (strip xml declarations, `#fff` → `currentColor`).

Two ready-made packs ship as sub-entries: `@jixoai/ui-vite-plugin/spinners/magecdn` (94 loaders, each pixel-verified) and `@jixoai/ui-vite-plugin/spinners/svg-loaders` (SamHerbert's 12, upstream credit).

![pack breadth: 24 of the magecdn pack's 94 loaders (every fourth), currentColor painting — effect only, no page text](/blog-assets/2026-09-13-ui-0-5-0/spinner-packs.png)

```ts
import { magecdnSpinners } from '@jixoai/ui-vite-plugin/spinners/magecdn';
import { svgLoadersSpinners } from '@jixoai/ui-vite-plugin/spinners/svg-loaders';
import { jixoai } from '@jixoai/ui-vite-plugin';

export default defineConfig({
  plugins: [
    jixoai({
      spinners: {
        spinners: {
          ...magecdnSpinners,
          ...svgLoadersSpinners, // same-name entries override by spread order (the icons law)
        },
      },
    }),
  ],
});
```

## The rest

- **Baseline debt cleared**: a0a512e9 added gripVertical as the 39th built-in icon without re-recording the frozen expectations — 14 suite failures sitting on main. This release re-records every place the manifest length is law — plugin suite 489/489, the first fully green run since a0a512e9; verify:all GREEN end-to-end.
- **Playground controls standardized**: PlayTiming (an auto | custom segmented pair + gated number inputs), PlaySegmented growing a `bind:` channel, and PlayNumber rewritten to event-driven commits — typing 32 no longer snaps back to 16 under a stale resync.
- **The density ruler arrives**: the jixoai.com site-level typography vocabulary (`--jx-text` / `--jx-icon`) becomes the anchor for spin sizing.
- The remaining 12 fix commits are walk-through rounds' scraps.
