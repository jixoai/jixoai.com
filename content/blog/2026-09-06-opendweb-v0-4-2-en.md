OpenDWeb v0.4.2 is out (2026-09-06, the first GitHub Release on [jixoai/opendweb](https://github.com/jixoai/opendweb)). This release documents the published state of all six npm packages; from the next tag on, the [release workflow](https://github.com/jixoai/opendweb/blob/main/.github/workflows/release.yml)'s automated release notes take over.

## Background: a system-level VPN, or building it from zero

When a multi-device application needs networking, the existing answers are either a system-level VPN with frighteningly broad permissions covering every device and all traffic, or every app building its own from zero. OpenDWeb (opendweb) argues for a third path: **application-level logical networks**, where devices join the network only by invitation, four layers each with its job:

```text
Identity  Ed25519 EndpointId (stable identity, decoupled from network
          addresses; z-base-32 display form)
Roster    signed facts (Genesis/Grant/Join/Revoke), content-addressed
          (BLAKE3) + union-merge convergence; controlled invites via
          issuer-online single redemption (challenge-response PoP +
          invite_id CAS consumption)
Session   iroh 1.1: QUIC direct + NAT traversal + self-hosted relay
          fallback; dual ALPN (regular/redeem); gating on both sides
          (gate before data); per-frame resource caps
Sync      opaque envelopes, bidirectional send/receive (Automerge
          adapter planned as a separate change)
```

Invites must be **redeemed while the inviter is online** (issuer-online single redemption): the inviter's process (e.g. a `chat` session) must stay running during redemption. Join failures carry stable error codes (`error[join/<code>]`). `NO_REACHABLE_PATH` fails instantly with guidance. `DIAL_TIMEOUT` notes the issuer is likely offline.

## Self-host in one command, one entry for clients

The server is one command (or one container). Clients need exactly **one** config entry. The gateway discovers the relay via `/services.json`, so no client ever has to know that port 3340 exists:

```bash
# 1. Start the server (gateway + relay)
npx opendweb server
#   or: docker run -p 8787:8787 -p 3340:3340 ghcr.io/gaubee/dweb:0.4.2

# 2. One-time config per client machine (persisted to ~/.opendweb/config.json)
npx @jixo/opendweb-example config set relay http://192.168.2.13:8787

# 3. Terminal A: initialize and keep a chat session running (signs invites)
npx @jixo/opendweb-example init --data ~/.dweb-a
npx @jixo/opendweb-example invite --data ~/.dweb-a --ttl 30m   # copy the token
npx @jixo/opendweb-example chat --data ~/.dweb-a

# 4. Terminal B (another directory/device): redeem the invite and chat
npx @jixo/opendweb-example join --data ~/.dweb-b <token>
npx @jixo/opendweb-example chat --data ~/.dweb-b
```

Verify a running server: `curl http://localhost:8787/healthz` → 200; `curl http://localhost:8787/services.json` → the service manifest. End-to-end regression has a manual: [EXAMPLE.md](https://github.com/jixoai/opendweb/blob/main/EXAMPLE.md) ([Chinese version](https://github.com/jixoai/opendweb/blob/main/EXAMPLE-zh.md)). Walk it after every release.

## Two highlights of the 0.4.x line

- **Plugin installs pin `@latest` explicitly**: installing a plugin now states exactly which version it wants (`opendweb plugin add cf` installs and locks `name@version`), so an ancestor-directory `package.json` with a stale dependency range can no longer hijack version resolution (the content of [v1.0.1-cli](https://github.com/jixoai/opendweb/releases/tag/v1.0.1-cli)).
- **The ext-cf 1.0 rewrite**: putting a server without a public IP behind a Cloudflare Tunnel takes one browser login or one pasted API token; the control plane goes through an SDK, cloudflared can be left to the plugin, and the token-paste UX accepts whole blocks or single entries. The rewrite went through a Codex-reviewed remediation round (SDK leaf imports, config-merge PUT, the OAuth persistence contract, install-path and race fixes). Earlier, `v0.4.0` split connector vs management credentials (a live 401 fix).

## Upgrade

```bash
npx opendweb@0.4.2 server          # or: npm i -g opendweb@0.4.2
npm i @jixo/opendweb-client-sdk@0.3.2
docker run -d -p 8787:8787 -p 3340:3340 ghcr.io/gaubee/dweb:0.4.2
```

The v0.4.2 image ships from the historical namespace `ghcr.io/gaubee/dweb` (the pull commands above already use it); builds published after the repository rename to `jixoai/opendweb` move to `ghcr.io/jixoai/opendweb`.
