OpenTray v0.21.1 is out (2026-09-06, the repo's first GitHub Release). The main business of this release is release automation: every published version cuts a GitHub Release of its own, and this site's version pill turned from "v—" to v0.21.1 for the first time. create-opentray 0.21.0's fresh-install 404 is fixed in the same cut, making this the first installable release of command families (the runner-family command input introduced in 0.21.0).

## Release automation: every version gets a GitHub Release

Until now this repo published npm packages via changesets, with **zero GitHub Releases**; if you wanted a version's change record, GitHub had no page for it. This site's pill read "v—" and the org blog had no release to link. The [change proposal](https://github.com/jixoai/opentray/blob/main/openspec/changes/archive/2026-09-06-release-automation-and-copy/proposal.md) closed that: every published version also cuts a GitHub Release (tag = the package version, notes = the changesets-generated changelog section), and a `workflow_dispatch` input can backfill a release for the current version (the bootstrap path). opentray@0.21.1 is the first one, cut via that bootstrap path. From the next version on, release notes are fully automated.

## Background: lightweight tools deserve a system-level entry

OpenTray's product goal has never stopped at "showing a tray icon." The [AGENTS.md Vision](https://github.com/jixoai/opentray/blob/main/AGENTS.md) says it in one line: give lightweight tools a system-level entry point **without forcing users into Electron or a full desktop app framework**. CLI tools, AI skills, and local daemons deserve a resident status surface and a click entry, but a hundred-MB runtime for one small icon does not add up.

The current answer is the tray-first platform model, four atoms with these roles.

- `App`: the caller-owned runtime identity and isolation boundary
- `Tray`: one desktop status atom owned by that app/runtime
- `Session`: the live source of authority for tray events and mutations
- `Extension`: an optional native capability atom scoped to app and tray

Application code calls `createTray()` directly and owns its own foreground/background lifetime (the `Space`/`Surface` ontology of the previous public API has retired). The first app needs no bundler and loads no Node addon. Ordinary app code talks to the runtime over the public tray/session protocol:

```ts
import { createTray, type TrayIcon } from "opentray";

let tray;
tray = await createTray(
  {
    id: "com.example.first-app",
    icon: { "text-only": "OT" },
    menu: {
      items: [
        { title: "Quit", primaryEvent: true, onMenuClick: () => void tray.destroy() },
      ],
    },
  },
  { appId: "com.example.first-app", appName: "First App" },
);
```

The workspace publishes all its packages on one fixed version: `opentray` (SDK + CLI), `@opentray/spec` (the protocol contract), `@opentray/packaging` with four bundler adapters (vite/tsdown/esbuild/webpack writing the same manifest shape), `@opentray/ext-webview` with platform WebView dynamic libraries, `@opentray/ext-badge`; the Lynx extension lives in its own repo, [jixoai/opentray-ext-lynx](https://github.com/jixoai/opentray-ext-lynx).

## One command turns an existing command into a tray app

Already have a command that serves HTTP locally? `npx create-opentray` wraps it into an OpenTray-hosted app. All three entry paths are in the [create-app guide](https://github.com/jixoai/opentray/blob/main/skills/opentray/references/create-app.md).

```bash
npx create-opentray web      # browser wizard, interactive
npx create-opentray create --app-id com.example.build \
  --app-name "Build" --exec "npm run dev"   # fully non-interactive
npx create-opentray skill    # the built-in AI skill, for agents to read
```

The 0.21.0 command families collapsed the wizard's command input into a single-row input group: a family-selector prefix plus the command body. npm (npx/pnpx/bunx/yarn dlx/nubx/deno run/vpx), `go run`, `cargo install`, `uvx/pipx run`, and `dnx` each render a read-only command surface opening a structured form (runner, package/module/crate/tool id, version, arguments); confirm writes the command string back, cancel discards the whole input. The family-aware appId derivation gives the same package a stable identity across runners.

```text
npx @deepseek-ai/dsh@latest web   → web.dsh.npmjs
go run rsc.io/fortune@latest      → fortune.golang
cargo install ripgrep (rg)        → rg.rust
```

## Other changes

- Fixed create-opentray 0.21.0's fresh-install 404 (the private workspace packages `@create-opentray/core` and `@create-opentray/cli` shipped in runtime `dependencies`; [0b0fe63](https://github.com/jixoai/opentray/commit/0b0fe632))
- `@opentray/spec`, `@opentray/packaging`, and `@opentray/vite-plugin` are published at 0.21.1 with it

## Upgrade

```bash
npm i create-opentray@0.21.1   # mandatory for 0.21.0 users (it never installed)
npm i opentray@0.21.1          # the SDK, same line
```

When using official extensions, lock the same protocol line: `pnpm add opentray@stable-A-B @opentray/ext-webview@stable-A-B` (protocol-line tags are published by `@opentray/spec`; do not mix with `latest`).
