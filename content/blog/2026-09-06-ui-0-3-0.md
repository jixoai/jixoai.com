jixoai-ui v0.3.0 发布了（2026-09-05）。这一版的主菜，用 [release commit](https://github.com/jixoai-ui/commit/125e31f1) 自己的话说，是 **"the document-ontology era"**：registry 开始承载文档的结构本体。

## 背景：从「设计语言 registry」到「文档本体」

0.2.0 时代的 jixoai-ui 是 shadcn registry 形式的设计语言：终端美学、OKLCH 单色相法则、拷贝即所有的组件。0.3.0 的主张变化源自一个研究问题（Owner 原话，[2026-09-02 设计轨](https://github.com/jixoai-ui/blob/main/openspec/changes/2026-09-02-document-ontology/proposal.md)）：「假如你是创作者，你需要什么样的结构化表达？」词典学家想的是词头/词性/分义号/书证，作曲家想的是乐章/小节/排练标记。今日的 web 文档只给他们 heading + code block。

设计轨给出的答案是三层本体：**点 = CodeBlock**（表达原子）、**线 = SectionCard**（跨行业提取的结构原语最小集，7 原语：节/条/列/浮/注/引/断）、**面 = PrintDoc**（体裁预设）。这正是 Markdown 之于写作者的历史重演：几个记号换来整个写作 Web，20% 的词汇覆盖 80% 的结构（设计轨原话）。首个消费者是收割合同。结构落地后，搜索、llms.txt、打印 ToC 自动变准，零返工。v0.3.0 是这套本体第一个大规模实施窗口：786 个提交，其中 270 个 feat、261 个 fix。

## 编号有了本体归属：计数域 + Figure（浮）+ Reference（引）

编号引用一直是 PagedRef 退役后的未尽事宜。没有本体归属，工具书/教材页无从谈起（[R2 提案](https://github.com/jixoai-ui/blob/main/openspec/changes/archive/2026-09-04-document-ontology-r2-float-reference/proposal.md)的原始动机）。R2 在这个版本全量落地，落在三件事上。

- **Section 计数域**：`numbering` 声明让一个节成为编号子树根 + 浮计数域，节十进制树自动生长（3 → 3.2 → 3.2.1）；**不在任何域子树内的节逐字节不变**。
- **Figure 家族**（`kind`：figure | table | equation | listing）：线承载结构（编号/锚/图注），点嵌内容槽；另有 `citedIn` 手动反链标注。
- **Reference 家族**：目标自述语法，解析完全跟随目标。编号 Figure → `Eq (4.5)`，编号节 → `§ 3.2.1`，无编号 → 目标标题；缺失 id 响亮回退（console.warn + 可见标记，永不阻塞）。

来自 v0.3.0 文档页的真实用法：

```svelte
<NumberingProvider>
  <Section numbering="decimal" title="Results">
    <Figure kind="equation" id="eq-1" caption="the momentum balance">
      <CodeCard lang="ts">p = m·v</CodeCard>
    </Figure>
    <p>see <Reference to="eq-1" /></p>
  </Section>
</NumberingProvider>
```

收割侧配套两趟预扫描：第一趟建全文档可引目标索引，第二趟把 `data-ref-to` 投影进取。前向引用的 SSR 回退态也能携带边主张，静态语料完整。figure 的 `number`、引用点块的 `refids[]`、section 的 `number` 都进了收割合同，骑的是 R1 已落地的 data 标记车道。整个 R2 收尾时，全仓测试套件落在 **2185/2185**（[604f9e01](https://github.com/jixoai-ui/commit/604f9e01)）。

## 显示货币法则：CSS counters 与 PagedRef 退役

编号是 **DOM 顺序的显示货币**：换序即重排、id 不动。这条法则让打印零特判。编号已经在 DOM 里，打印管线原样捕获；folio（页码）仍归布局事实，永不预收割。CSS counters 与 PagedRef 这两套旧编号机制正式退役。

## 不止编号：786 个提交的其余大盘

- **press physics 轴**：raised/flat 双区、engrave 二重奏，icon-button 入轴，按压物理从单组件法则升级为全库坐标轴
- **scroll-run**：所有可滚动区域统一为一套共享法则（新 registry 条目 `@jixoai/scroll-run`），tabs 与 button-group 都成了它的消费者；slide/blur/blurSlide/progressBlur/shadow 五种效果由同一法则集供给，RTL 在三引擎上规范化（[aeb747f2](https://github.com/jixoai-ui/commit/aeb747f2)）
- **2xs 密度档**：第五档密度，面向专业工具操作面的极致紧凑。文字 10px（9px 保持不发，作为绝对下限），行高 24px 踩在 WCAG 2.5.8 AA 下限，命中下限按非触控指针立场在档内重声明（[c8749f86](https://github.com/jixoai-ui/commit/c8749f86)）
- **打印确定性**：viewport 无关的打印输出
- **defaults-economy 三部曲 + 单一 paint key**；**control-chrome**（行内控件壳层的溶解/自持二态）
- **ghostty pin 与 lock-chain CI 修复**

到这个版本，registry 收录 **113 个条目**。

## 同船：@jixoai/vite-plugin 0.2.0

仓库内同船搭载 [vite-plugin 0.2.0](https://github.com/jixoai-ui/tree/v0.3.0/packages/vite-plugin)：钉版本的 ghostty-vt wasm（resolve → serve → emit → 经 `virtual:jixoai-ghostty` 交 URL）、图标系统（svg/lucide/font providers）与 `jixoai-ghostty-probe` ABI 哨兵 bin。ghostty pin 解析器与 lucide lock 同步修复了它的安装问题（release commit 原话）。

## 迁移（破坏性：data-jx 钩子）

0.3.0 窗口内含一次破坏性变更（2026-08-25）：css-less 的 `.jx-*` 钩子类全面退役，语义锚改为 `data-jx-*` 属性，**不保留兼容类**。查询迁移：

```diff
- document.querySelector('.jx-kbd')
+ document.querySelector('[data-jx-kbd]')
- '.jx-badge-destructive'
+ '[data-jx-badge="tonal"]'
- el.classList.add('jx-foo')
+ el.setAttribute('data-jx-foo', '')
- el.classList.contains('jx-foo')
+ el.hasAttribute('data-jx-foo')
```

变体族合并为单一有值属性（`data-jx-badge={variant}`，阶梯 `fill | tonal | outline` 只含结构值，语义色名不进阶梯；error 状态 = `variant="tonal"` + `jx-hue-error` 注入）。最低摩擦路径：`npx shadcn add @jixoai/<item>` 重拉条目，再按上表迁移查询。
