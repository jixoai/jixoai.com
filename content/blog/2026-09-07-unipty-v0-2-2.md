UniPty v0.2.2 发布了（GitHub Release 于 2026-09-07 20:53 UTC 切出）。这一版只动一个包：`@unipty/backend-zigpty` 升到 0.2.1，核心是两件事。zigpty 路由在 Windows 上从拒绝就绪改为可运行；输出侧新增一个可选的磁盘化缓冲 `outputSpool`。Core 与另外三条路由零改动。

## Windows：从门禁到适配

[v0.2.1](/blog/2026-09-07-unipty-v0-2-1/) 引入这条路由时，Windows 上是失败关闭的：引擎的 ConPTY 预编译齐全，但其 Windows 实现的 `pause()` / `resume()` 是空方法（zigpty 0.2.1 的 `WindowsPty`），消费端驱动的输出背压传导不到内核。适配器因此拒绝就绪，而不是带着一个会无限增长的队列运行。当时的解除条件写的是"等上游补上流控"。

这一版不等了。UniPty 约束不了所有引擎，第三方开发者会有自己的 backend，用适配层弥合引擎差异本来就是这套架构的重点工作。门禁撤掉后，路由在 Windows 上照常运行：适配器持续排空引擎回调，代价如实声明为"输出背压在该平台传导不到内核"，与 Deno 路由对内部读线程的处理是同一类声明式限制。安装与启动不需要任何平台分支：

```ts
const backend = await createZigptyBackend(); // Windows 与 unix 同一行
```

支持声明仍由证据门控。Windows 元组在拿到公开契约证据之前保持 declared-unverified，[兼容性目录](https://unipty.jixoai.com/compatibility)如实呈现，门禁的撤除不等于验证的支持。

## outputSpool：磁盘化的输出缓冲

停读的消费者是内存的主要风险。终端挂到浏览器标签页上，用户切走十分钟，引擎在这十分钟里产出的输出没有去处，只能堆在适配器的队列里。Windows 之外这个问题同样存在，只是 unix 上内核背压会把压力还给子进程，堆不快。

`outputSpool` 把这个队列换成磁盘化的 FIFO：

```ts
const backend = await createZigptyBackend({
  outputSpool: { memoryBytes: 4 * 1024 * 1024 }, // 或直接 true 用默认值
});
```

机制是三段。内存头默认 1 MiB 封顶；越界的记录溢写到适配器自有的临时文件；回放严格跟随消费端的拉动节奏，流的水位线之外不多塞一条记录。公开流的字节与不开时完全一致：文本记录按完整记录往返，chunk 边界保持不变。子进程退出时，完成信号会等积压排空才发出，快退输出的尾巴不会被 EOF 截断；显式 `close()` 仍然同步完成并删除临时文件。

三个使用前需要知道的边界。溢写是同步 IO；积压期间的磁盘占用按设计不设上限，只受子进程自身输出量约束；进程被强杀时临时文件交由系统临时目录清理。在引擎能够暂停的平台上（unix），越过内存界还会把压力传导回内核，阻塞子进程而不是继续堆积。

这条路径过了完整的边界测试：70 项包测试覆盖洪水与慢读者的顺序完整性、无人读取时的完整回放、积压中的取消与清理、损坏记录的拒绝，25 个场景的公共契约套件对装配产物复验通过。发布前另有两轮独立复核，第一轮提出的三个阻塞问题（取消路径的传输释放悬挂、运行时选项校验、规格校验）全部修复后二轮通过。

## 其余变更

- 修复被暂停读取的洪水子进程收不到终止确认：引擎在积压未排空时会推迟退出观察，`terminate()` 现在在 kill 后恢复读取（[9bac5d7](https://github.com/jixoai/unipty/commit/9bac5d7)）
- 修复 `close()` 后读取暂停导致的同类悬挂，关闭后数据走丢弃路径（[9bac5d7](https://github.com/jixoai/unipty/commit/9bac5d7)）
- 变更全程记录在 OpenSpec 变更 zigpty-windows-soft-support（[65f053b](https://github.com/jixoai/unipty/commit/65f053b)）

完整清单见 [compare v0.2.1...v0.2.2](https://github.com/jixoai/unipty/compare/v0.2.1...v0.2.2)。

## 升级

zigpty 路由用户升一个包即可，其余路由无需动作：

```bash
npm i @unipty/backend-zigpty@0.2.1
```

`outputSpool` 默认关闭，不开则行为与 0.2.0 逐字节一致。
