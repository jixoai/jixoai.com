OpenTray 0.33.0 through 0.34.1 carries two themes: transport recovery turns uninvited broker death into a zero-config in-process recovery, and `bindWindowRegion()` lets pages drive native window behavior through a declarative API. The rest is six real-machine Windows fixes and one release realignment. The previous post covered up to 0.32.0; this one covers every change in the range grouped by theme, with permanent release links at the end.

## Transport recovery (0.33.0)

A tray tool now ships with zero recovery code of its own: after the broker process is killed with kill -9, the SDK reconnects and rebuilds state inside the same process, and the consumer only hears about it through a state event.

The mechanism has two layers. First, every SDK call is deadline-bounded (interactive 5 s, teardown 2 s, bootstrap 10 s, overridable per call) and settles with a typed `TransportTimeoutError` instead of hanging. Deferred operations the user is holding, such as a dialog waiting for a click, are exempt from the deadline; they settle only through their terminal frame. Second, socket close or a half-open connection detected by the heartbeat triggers automatic recovery: after cooldown backoff the broker is respawned through the same identity-gated connect path, with artifact identity checks and lock reclaim reapplied, then tray and WebView state replay declaratively, and a full state snapshot is re-emitted last. The recovery budget defaults to 3 attempts per 10 minutes. Once exhausted, calls fail fast with `TransportAbandonedError` and the runtime enters the terminal `abandoned` state while the app keeps running headless.

```ts
const tray = await createTray(
  { id: "com.example.tool", tooltip: { title: "tool" } },
  { appId: "com.example.tool", appName: "Tool" }
);

tray.onTransportStateChange?.((state) => {
  // "healthy" | "recovering" | "abandoned"
  setUiStatus(state);
});
```

Every recovery knob has a working default; configuring nothing is full protection. Apps that prefer a process-level hand-over pass `runtimeOptions.recovery.restartApp`, and the supervisor performs a bounded teardown, invokes the callback exactly once, and goes terminal.

Hardening followed. 0.33.1 fixed shutdown racing recovery, made the heartbeat single-flight per generation, and bounded each reconnect attempt. 0.33.2 keeps each window's settled visibility after recovery, so a hidden retained window no longer pops back open. 0.33.3 holds the host event loop across the death-to-reconnect window, so a bare process with no loop holder of its own no longer exits mid-recovery (real-machine evidence 2026-09-22). The test suite gained a permanent kill -9 drill gate and a bare-child-process leg.

## Declarative window regions (0.34.0)

Pages no longer hand-wire pointerdown handlers to drive native window chrome. `navigator.opentrayWindow.bindWindowRegion(target, behavior)` binds an element, an element array, a selector, or `{ root, selector }` to native window behaviors. Matching is strict: only presses whose target is the bound element itself trigger behavior, and descendants keep their normal interactivity.

```ts
const bridge = navigator.opentrayWindow;

bridge.bindWindowRegion(titlebar, "auto"); // move + double-click maximize/restore
bridge.bindWindowRegion(dragStrip, "move");
const grip = bridge.bindWindowRegion(gripEl, "resize-bottom-right");
grip.setBehavior("none"); // pause without unbinding
```

The behaviors are `'auto'` (the default, platform caption semantics: move on press plus double-click zoom), `'none'`, `'move'`, `'zoom'`, and `resize-<edge>` (`resize-top` through `resize-bottom-right`, eight directions). Resize handles require a frameless window; macOS now serves them through the same internal command Windows already has, backed by a native soft-resize session where a local event monitor drives `setFrame` through the drag. Selector matches snapshot at bind time, and rebinding an element replaces its previous binding.

The same release fixes the win32 overlay titlebar band: `ExtendsContentIntoTitlebar` claimed the whole band as a native drag region, so interactive controls a page placed in its custom titlebar were unclickable. The overlay apply path now installs a degenerate drag rectangle, which returns the band to normal client input ([e9823dc](https://github.com/jixoai/opentray/commit/e9823dc)).

## Other changes

- Fixed: win32 notifications were completely invisible on current Windows 11 (the staged binary predated the notification bridge, `NIIF_NONE` is silently dropped by the OS, and balloons stop presenting after the tray flyout is opened while the API keeps returning TRUE; real-machine evidence 2026-09-23). Delivery moved to WinRT toasts under a per-app AUMID with a long-lived worker thread ([ce1bf51](https://github.com/jixoai/opentray/commit/ce1bf51)).
- Fixed: win32 text-only tray titles rendered as transparent slots; they are now rasterized into RGBA icons through GDI and follow the taskbar theme ([c806ed2](https://github.com/jixoai/opentray/commit/c806ed2)).
- Fixed: win32 layout-transaction re-entrancy aborted the broker with 0xC0000409 (real-machine evidence 2026-09-24); every borrow inside relayout is now a `try_borrow` behind a per-window re-entrancy ledger ([9dc1213](https://github.com/jixoai/opentray/commit/9dc1213)).
- Fixed: the win32 titlebar overlay failed with os error 126 on machines whose runtimes are only OS-provisioned; the fallback adds the runtime package to the process graph through the OS-public Package Dependency APIs (real-machine evidence 2026-09-28, [2a08658](https://github.com/jixoai/opentray/commit/2a08658)).
- Fixed: win32 pixel-sourced tray icons now register at the tray's physical slot size, and `isTemplate` theme tinting works on win32 ([e1ff250](https://github.com/jixoai/opentray/commit/e1ff250)).
- Fixed: darwin bare-script consumers (entry script with no package.json ancestor) crashed at connect; package identity resolution now falls through to the ambient/cwd fallbacks ([b90bef4](https://github.com/jixoai/opentray/commit/b90bef4), 0.34.1).
- Release: the 0.33.4 workflow skipped `@opentray/icon`; 0.33.5 re-versioned the fixed group to republish and realign ([3ddd839](https://github.com/jixoai/opentray/commit/3ddd839)).
- Docs: the consumer skill references cover the toast channel, recovery budgets, and `isTemplate` platform guidance; examples gained notify-repro, dialog-selftest, webview-recovery, and a window-region smoke.

No breaking changes in this range. 54 commits after 0.32.0: 5 feat, 14 fix, 16 docs, 4 test, 15 chore, counted by conventional-commit prefix.
