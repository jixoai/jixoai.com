OpenTray 0.33.0 到 0.34.1 有两个主题：transport 恢复把 broker 非受邀死亡变成零配置的进程内自恢复；`bindWindowRegion()` 让页面用声明式 API 驱动原生窗口行为。其余是六个 Windows 实机修复和一次发布对齐。上一篇讲到 0.32.0，本篇按主题归组覆盖区间全部变更，链接栏列出每个版本的 release 永链。

## transport 恢复（0.33.0）

托盘工具现在可以不写任何恢复代码：broker 进程被 kill -9 后，SDK 在同一个进程里完成重连与状态重建，调用方只通过状态事件知情。

机制分两层。第一层，每个 SDK 调用都有截止时限（交互 5 s / 收尾 2 s / 引导 10 s，可按调用覆盖），超时以类型化的 `TransportTimeoutError` 落定，不再挂死；用户手上的延迟操作（等一次点击的对话框）不受时限影响，只经终帧落定。第二层，socket 关闭或心跳探到的半开连接触发自动恢复：冷却退避后经同一条身份门控路径重生 broker，工件身份校验与锁回收全部重放，然后声明式重放托盘与 WebView 状态，最后全量快照重发。恢复预算默认 10 分钟 3 次。耗尽后调用 fail-fast（`TransportAbandonedError`）并进入终态 `abandoned`，应用以无头模式继续运行。

```ts
const tray = await createTray(
  { id: "com.example.tool", tooltip: { title: "tool" } },
  { appId: "com.example.tool", appName: "Tool" }
);

tray.onTransportStateChange?.((state) => {
  // "healthy" | "recovering" | "abandoned"
  setUiStatus(state);
});
```

恢复旋钮都有默认值，不配置即完整保护；需要进程级接管的应用传 `runtimeOptions.recovery.restartApp`，监督层做有界收尾后恰好调用一次回调并进入终态。

后续加固：0.33.1 修复恢复与关闭的竞争、心跳改为每代单飞并给每次重连加时限；0.33.2 在恢复后保持窗口既定可见性，隐藏的保留窗口不再被重新弹出；0.33.3 让监督层在死亡→重连窗口内持有宿主事件循环，除 broker 连接外没有别的循环持有者的裸进程不再在恢复中途退出（实机证据 2026-09-22）。测试套件增加了永久的 kill -9 演习门和裸子进程腿。

## 声明式窗口区域（0.34.0）

页面不再手写 pointerdown 处理器驱动原生窗口。`navigator.opentrayWindow.bindWindowRegion(target, behavior)` 把元素、元素数组、选择器或 `{ root, selector }` 绑定到原生窗口行为。匹配是严格的：只有按压目标是被绑定元素本身才触发，后代保持普通页面交互。

```ts
const bridge = navigator.opentrayWindow;

bridge.bindWindowRegion(titlebar, "auto"); // 移动 + 双击最大化/还原
bridge.bindWindowRegion(dragStrip, "move");
const grip = bridge.bindWindowRegion(gripEl, "resize-bottom-right");
grip.setBehavior("none"); // 暂停，不解绑
```

可选行为是 `'auto'`（默认，平台标题栏语义：按压移动加双击缩放）、`'none'`、`'move'`、`'zoom'` 和 `resize-<edge>`（`resize-top` 到 `resize-bottom-right` 八向）。resize 手柄要求 frameless 窗口，macOS 在 Windows 已有的同一条内部命令背后补上原生 soft-resize 会话，由本地事件监视器在拖拽全程驱动 `setFrame`。选择器匹配是绑定时的快照，重新绑定同一元素会替换旧绑定。

同一版本修复了 win32 overlay 标题带输入：`ExtendsContentIntoTitlebar` 此前把整条标题带划为原生拖拽区，页面放进自定义标题栏的交互控件点不到，现在装入退化拖拽矩形把输入还给页面（[e9823dc](https://github.com/jixoai/opentray/commit/e9823dc)）。

## 其余变更

- 修复：win32 通知在当前 Windows 11 上完全不可见（暂存二进制早于通知桥、`NIIF_NONE` 被系统静默丢弃、气泡在托盘浮层打开后停摆而 API 仍返回成功；实机证据 2026-09-23），投递改走每应用 AUMID 下的 WinRT toast 与长驻工作线程（[ce1bf51](https://github.com/jixoai/opentray/commit/ce1bf51)）。
- 修复：win32 文字托盘图标此前渲染为透明槽位，现在经 GDI 栅格化为 RGBA 图标并跟随任务栏主题（[c806ed2](https://github.com/jixoai/opentray/commit/c806ed2)）。
- 修复：win32 布局事务重入导致 broker 以 0xC0000409 中止（实机证据 2026-09-24），布局内借用全部改 `try_borrow` 并加每窗口重入台账（[9dc1213](https://github.com/jixoai/opentray/commit/9dc1213)）。
- 修复：win32 标题栏 overlay 在仅有 OS 预置运行时的机器上以 os error 126 失败，回退到 OS 公开的 Package Dependency API 直挂包图（实机证据 2026-09-28，[2a08658](https://github.com/jixoai/opentray/commit/2a08658)）。
- 修复：win32 像素托盘图标改为按物理槽位尺寸降采样注册，`isTemplate` 主题着色在 win32 生效（[e1ff250](https://github.com/jixoai/opentray/commit/e1ff250)）。
- 修复：darwin 裸脚本消费者（入口脚本没有 package.json 祖先）在连接时崩溃，包身份解析改为穷尽后回落环境/cwd 兜底链（[b90bef4](https://github.com/jixoai/opentray/commit/b90bef4)，0.34.1）。
- 发布：0.33.4 的发布流程漏发 `@opentray/icon`，0.33.5 重新版本化固定组补发对齐（[3ddd839](https://github.com/jixoai/opentray/commit/3ddd839)）。
- 文档：消费者 skill 刷新了 toast 通道、恢复预算与 `isTemplate` 平台准则；示例新增 notify-repro、dialog-selftest、webview-recovery 与窗口区域冒烟。

本区间无破坏性变更。0.32.0 之后 54 个提交：5 feat / 14 fix / 16 docs / 4 test / 15 chore（口径为 conventional 提交前缀计数）。
