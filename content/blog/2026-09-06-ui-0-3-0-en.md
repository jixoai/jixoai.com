jixoai-ui v0.3.0 is out (2026-09-05). What this release is about, in the [release commit](https://github.com/jixoai-ui/commit/125e31f1)'s own words, is **"the document-ontology era"**: the registry starts carrying the structural ontology of documents.

## Background: from a design-language registry to a document ontology

The 0.2.0-era jixoai-ui was a design language distributed as a shadcn registry: terminal aesthetics, the OKLCH one-hue law, components you own after copying. The 0.3.0 shift in stance traces back to one research question (the Owner's words, in the [2026-09-02 design track](https://github.com/jixoai-ui/blob/main/openspec/changes/2026-09-02-document-ontology/proposal.md)): "If you were a creator, what structured expression would you need?" A lexicographer thinks in headword/part-of-speech/sense-number/citation; a composer thinks in movement/bar/rehearsal mark. Today's web documents offer them nothing but headings and code blocks.

The design track's answer is a three-layer ontology: **point = CodeBlock** (the expression atom), **line = SectionCard** (the minimal set of cross-domain structural primitives, seven of them), **plane = PrintDoc** (genre presets). Markdown did the same thing for writers: a handful of notations bought the whole writing Web, 20% of vocabulary covering 80% of structure (the design track's own words). The first consumer is the harvest contract (the agreement that collects structural data from the rendered DOM into the static corpus). Once structure lands, search, llms.txt, and print ToCs get more accurate with zero rework. v0.3.0 is the first large implementation window for that ontology: 786 commits, 270 of them feat and 261 fix.

## Numbering and cross-references: domains + Figure (浮) + Reference (引)

As of this release, figures, tables, equations, and listings in a document number themselves automatically, and the running text can cite them anywhere. Numbered citation was the unfinished business PagedRef left behind: without an ontological home, reference-book and textbook pages were out of reach (the original motivation of the [R2 proposal](https://github.com/jixoai-ui/blob/main/openspec/changes/archive/2026-09-04-document-ontology-r2-float-reference/proposal.md); R2 is the second phase of the document-ontology plan). That phase lands whole in this release, in three parts.

- **Section numbering domains**: a `numbering` declaration makes a section the root of a numbering subtree + a float-counting domain, and decimal numbers generate level by level on their own (3 → 3.2 → 3.2.1); **sections outside any domain subtree stay byte-identical**.
- **The Figure family** (`kind`: figure | table | equation | listing): the line carries structure (number/anchor/caption), the point nests in the content slot; plus a `citedIn` manual back-reference slot.
- **The Reference family**: target-self-describing syntax, with resolution following the target entirely. A numbered Figure → `Eq (4.5)`, a numbered section → `§ 3.2.1`, an unnumbered one → the target's title; a missing id falls back explicitly (console.warn + a visible marker, never blocking).

Real usage from the v0.3.0 docs page:

```svelte
<NumberingProvider>
  <Section numbering="decimal" title="Results">
    <Figure kind="equation" id="eq-1" caption="the momentum balance">
      <CodeCard lang="ts">p = m·v</CodeCard>
    </Figure>
    <p>see <Reference to="eq-1" /></p>
  </Section>
</NumberingProvider>
```

The harvest side pairs it with a two-pass pre-scan: the first pass indexes every referenceable target in the document, the second maps `data-ref-to` onto the corpus. Forward references still record what they point to in the SSR fallback state, keeping the static corpus complete. The figure's `number`, the citing block's `refids[]`, and the section's `number` all entered the harvest contract, reusing the data markers R1 (the first phase) had already landed. When R2 wrapped, the repo-wide suite stood at **2185/2185** ([604f9e01](https://github.com/jixoai-ui/commit/604f9e01)).

## Numbers follow DOM order: CSS counters and PagedRef retire

Reorder sections and the numbers renumber on their own, link anchors keep working, and printing needs no special handling for numbering. Numbers follow DOM order directly: reorder and it renumbers, and the id never moves. The numbers are already in the DOM, and the print pipeline captures them as-is; folios (page numbers) remain layout facts, never pre-harvested. CSS counters and PagedRef, the two legacy numbering mechanisms, formally retire; the replacement is the `numbering` declaration and `Reference` from the previous section.

## Beyond numbering: the rest of the 786

- **Press physics**: raised/flat zones, the paired engrave effects, icon-button joining in, press physics going from a per-component rule to a library-wide rule
- **scroll-run**: every scrollable region unified under one shared law set (new registry item `@jixoai/scroll-run`), with tabs and button-group as its consumers; the five effects slide/blur/blurSlide/progressBlur/shadow all supplied by the same law set, RTL normalized across three engines ([aeb747f2](https://github.com/jixoai-ui/commit/aeb747f2))
- **The 2xs density rung**: the fifth density, the tightest compactness for pro-tool operation surfaces. Text lands at 10px (9px stays unshipped as the absolute floor), the 24px row sits at the WCAG 2.5.8 AA floor, and the hit floor is redeclared inside the rung per the non-touch-pointer stance ([c8749f86](https://github.com/jixoai-ui/commit/c8749f86))
- **Print determinism**: viewport-independent print output
- **The three defaults-economy changes + the single paint key**; **control-chrome** (the integrated/self duality of in-row control shells)
- **The ghostty version pin and lock-chain CI repairs**

As of this release the registry carries **113 items**.

## Ships with this release: @jixoai/vite-plugin 0.2.0

Vite projects can now wire jixoai-ui's terminal components and icon system straight into their build. [vite-plugin 0.2.0](https://github.com/jixoai-ui/tree/v0.3.0/packages/vite-plugin) ships with 0.3.0: the pinned ghostty-vt wasm (resolve → serve → emit → hand over the URL via `virtual:jixoai-ghostty`), the icon system (svg/lucide/font providers), and the `jixoai-ghostty-probe` ABI sentinel bin. The ghostty pin resolver and the lucide lock sync fix its installs (the release commit's words).

## Migration (breaking: data-jx hooks)

The 0.3.0 window contains one breaking change (2026-08-25): the css-less `.jx-*` hook classes are fully retired, semantic anchors become `data-jx-*` attributes, and **no compatibility classes are kept**. Query migration:

```diff
- document.querySelector('.jx-kbd')
+ document.querySelector('[data-jx-kbd]')
- '.jx-badge-destructive'
+ '[data-jx-badge="tonal"]'
- el.classList.add('jx-foo')
+ el.setAttribute('data-jx-foo', '')
- el.classList.contains('jx-foo')
+ el.hasAttribute('data-jx-foo')
```

Variant families collapse into one valued attribute (`data-jx-badge={variant}`, with the ladder `fill | tonal | outline` carrying structural values only and no semantic hue names; error status = `variant="tonal"` + `jx-hue-error` injection). The lowest-friction path: re-add items with `npx shadcn add @jixoai/<item>`, then migrate queries per the table above.
