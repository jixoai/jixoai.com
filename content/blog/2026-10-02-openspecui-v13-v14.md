OpenSpecUI v13 and v14 are released, adapting the interface to the OpenSpec CLI 1.13 and 1.14 lines. The user-visible changes concentrate in three areas: CLI notices render as expandable summary rows; task evidence carries source line numbers; supported Agent tools grow from 40 to 50. Protocol-level adaptation detail is collected in the collapsible blocks at the end.

## Notices expand on demand

Since v13, the change detail page shows Apply-stage warnings and the outstanding work order as a one-line summary that expands on click; since v14, advisory warnings from `openspec status` join the same presentation. When `.openspec.yaml` carries an unrecognized key, the CLI notice appears verbatim:

```text
1 status warning — openspec status          ← click to expand the full text
2 apply warnings · next in build order: specs → design
```

The two notice families cover:

1. Warnings about the change itself: a mistyped config key or missing delta specs, shown in the CLI's own words with the valid form stated (Apply output since v13, status output since v14)
2. The pre-Apply work order: unfinished artifacts listed in dependency order (v13)

Notices block nothing; Apply and archive buttons stay as available as before. The summary row stays collapsed by default and takes no page space on narrow screens.

## Evidence locates precisely

Since v14, every task in the apply list carries its source file path and line number (1-based in tasks.md), so task evidence points at an exact location. In the same version, requirement and scenario titles on spec pages use the names from the CLI's `show --type spec` output, matching the command line instead of being inferred from Markdown structure.

## Wider Agent tool support

The v14 Agent registry adds ten tools, bringing the total from 40 to 50:

> amp · atomcode · codestudio · dsh · easycode · gigacode · grok · gsd · veai · warp

Bob Shell is renamed IBM Bob, with commands and directories unchanged. During v13 the registry added no tools and only tracked upstream path moves (Kilo's commands moved to `.kilo/command/`).

## Upgrade

```bash
npm i -g @fission-ai/openspec@1.14
npx openspecui@latest
```

Each major maps to one CLI line: v14 to 1.14, v13 to 1.13, v12 to 1.12. To stay on an older line, use the matching OpenSpecUI version (for example `npx openspecui@13`). When an incompatible CLI is detected the interface opens a dialog; its "Skip version check" option applies to the current page only and clears on refresh.

<details>
<summary>Expand: the six CLI outputs v14 wires in</summary>

- `openspec version --json`: machine-readable version and install location
- `instructions apply`: `sourcePath` and `line` per task
- `list --archived` / `list --all`: distinguishes archived from in-progress changes
- `status`: top-level advisory warnings
- `show --type spec --json`: requirement and scenario names for specs
- `allowedEditRoots` on store-backed `status`: which directory a change should land in

</details>

<details>
<summary>Expand: the three v13 releases</summary>

1. **v13.0.0**: adapts to OpenSpec CLI 1.13; Apply notices (warnings and the work order) land on the change detail page
2. **v13.0.1**: adapts to CLI 1.13.1; the change list stops showing namespace directories as changes (`nested` detection); task checkboxes tolerate more Markdown styles
3. **v13.0.2**: adapts to CLI 1.13.2; glob-tracking evidence for task progress; Kilo command paths move

</details>

<details>
<summary>Expand: how the adaptation is verified</summary>

Every CLI-line switch runs the test matrix against the actually published CLI executable: the new line verifies the contracts hold, and the just-retired line (1.13.2) verifies the rejection behavior. The v14 adaptation went through 7 independent review rounds (5 planning, 2 implementation), recorded in the repository's [openspec archive](https://github.com/jixoai/openspecui/tree/main/openspec/changes/archive/2026-10-02-target-openspec-cli-114-line).

</details>
