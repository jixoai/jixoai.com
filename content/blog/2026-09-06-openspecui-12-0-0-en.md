OpenSpecUI 12.0.0 is out (2026-09-04). The headline is a full compatibility-window switch: adapting to the OpenSpec CLI 1.12 single series, while promoting validate's findings into a first-class evidence surface.

## Background: majors track the CLI minor lines

OpenSpecUI major versions ordinarily track OpenSpec CLI minor lines ([README compatibility table](https://github.com/jixoai/openspecui/blob/main/README.md)), from the 3.x line in June to 11.x in August, with a legacy README kept per historical line (1.11 / 1.9 / 1.7 / 1.6 / 1.3 / 1.2 / 1.x / 0.16). 12's window is **single-series**: `>=1.12.0 <1.13.0`, with stable 1.12.x as the current and recommended line; 1.10.x / 1.11.x (the OpenSpecUI 11 window) and older lines are blocked by default, as are prereleases and `>=1.13.0`. 1.13 is not pre-claimed. When it ships, admission is a separately verified decision (a 12.x window widening or a new major).

## validate --report findings: a capability-gated findings surface

12 turns "what validation found" from human-readable logs into a machine-consumable typed contract. `validate --report findings` is the new capability-gated contract and validation evidence surface: findings-only items delivered standalone while **preserving full-run totals and exit codes**, with request errors (`invalid_validation_report_request`) flowing through the shared diagnostic envelope. CI can consume just the findings without losing the full-run verdict.

The contract itself was tightened through review rounds: the findings argv owner gated and the workflow fixtures ported ([677cbe13](https://github.com/jixoai/openspecui/commit/677cbe13)); ahead of release, the evidence panels unified on a shared header contract and validation findings became attributed to their owning change ([1aa9ce43](https://github.com/jixoai/openspecui/commit/1aa9ce43), [13bb0e15](https://github.com/jixoai/openspecui/commit/13bb0e15)).

## Merge-conflict advisories: a first-class INFO level

The `Archive would refuse this delta` and `Could not check archive merge conflicts` advisories now render as a first-class informational (INFO) level **without changing validity evidence**. Advisories and failures formally part ways on the evidence surface, and pre-archive merge-conflict checks get their own severity for the first time.

## Agent delivery adds SourceCraft Code Assistant

The Agent delivery registry for 1.12 sessions gains another entry: SourceCraft Code Assistant (`.codeassistant`). Its skill references are natural language, its commands land at `.codeassistant/commands/opsx-<id>.md`, and adoption needs neither an IDE restart nor a migration step. The generator staleness baseline rotates to 1.12.0.

## Evidence method: pinned executable fixtures

The new contracts are not paper claims: the pinned `openspec-cli-112` fixture proves them, while the retained `openspec-cli-111` proves the capability-boundary rejections (how an older CLI gets blocked is itself tested). The fixture method tightened at the same time: the worktree endpoint fixture pins a hermetic CLI runner, and Windows lock-release retries are bounded ([0baa17a0](https://github.com/jixoai/openspecui/commit/0baa17a0), [2c602a53](https://github.com/jixoai/openspecui/commit/2c602a53)). Across the 24 commits from 11.1.0 to 12.0.0, the v12 fixture matrix, kernel findings transport, and evidence surfaces landed together ([d782c98e](https://github.com/jixoai/openspecui/commit/d782c98e)); the compatibility gate and Agent registry rotated ([9e0b0383](https://github.com/jixoai/openspecui/commit/9e0b0383), release entry [d272b1f](https://github.com/jixoai/openspecui/commit/d272b1f)).

## Migration (breaking: the compatibility window)

The window switch is breaking: 1.10.x / 1.11.x are blocked by default. The lowest-friction path is a one-line CLI upgrade:

```bash
npm install -g @fission-ai/openspec@1.12
```

If an incompatible CLI executable is genuinely at hand, the mismatch dialog offers **Skip version check**. The bypass is held only by the current page runtime and clears on refresh/reopen. It creates no compatibility promise.
