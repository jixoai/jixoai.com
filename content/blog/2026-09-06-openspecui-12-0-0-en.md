OpenSpecUI 12.0.0 is out (2026-09-04). The main content of this release is a full compatibility-window switch: adapting to the OpenSpec CLI 1.12 single series, while turning validate's findings into first-class machine-readable output.

## Background: majors track the CLI minor lines

OpenSpecUI major versions ordinarily track OpenSpec CLI minor lines ([README compatibility table](https://github.com/jixoai/openspecui/blob/main/README.md)), from the 3.x line in June to 11.x in August, with a legacy README kept per historical line (1.11 / 1.9 / 1.7 / 1.6 / 1.3 / 1.2 / 1.x / 0.16). 12's window is **single-series**: `>=1.12.0 <1.13.0`, with stable 1.12.x as the current and recommended line; 1.10.x / 1.11.x (the OpenSpecUI 11 window) and older lines are blocked by default, as are prereleases and `>=1.13.0`. 1.13 is not pre-claimed. When it ships, admission is a separately verified decision (a 12.x window widening or a new major).

## validate --report findings: machine-readable findings

Wiring validation results into CI used to mean parsing human-readable logs; `validate --report findings` now outputs machine-readable typed findings directly, so CI can consume just the findings without losing the full-run verdict. Findings-only items are delivered standalone while **preserving full-run totals and exit codes**; request errors (`invalid_validation_report_request`) return through the same structured diagnostic format. The output is capability-gated: only the 1.12-line CLI provides it, and older CLIs are explicitly rejected.

```bash
openspec validate --report findings
```

The contract itself was tightened through review rounds: the findings argv owner gated and the workflow fixtures ported ([677cbe13](https://github.com/jixoai/openspecui/commit/677cbe13)); ahead of release, the evidence panels unified on a shared header contract and validation findings became attributed to their owning change ([1aa9ce43](https://github.com/jixoai/openspecui/commit/1aa9ce43), [13bb0e15](https://github.com/jixoai/openspecui/commit/13bb0e15)).

## Merge-conflict advisories: a first-class INFO level

Merge-conflict advisories no longer sit mixed in with failures. The `Archive would refuse this delta` and `Could not check archive merge conflicts` advisories now render as a first-class informational (INFO) level **without changing validity evidence**, and pre-archive merge-conflict checks get their own severity for the first time.

## Agent delivery adds SourceCraft Code Assistant

SourceCraft Code Assistant users can now receive OpenSpecUI's agent delivery too: the skill references are natural language, the commands land at `.codeassistant/commands/opsx-<id>.md`, and adoption needs neither an IDE restart nor a migration step. The 1.12-session delivery registry thereby gains another entry (SourceCraft Code Assistant, `.codeassistant`), and the generator staleness baseline moves to 1.12.0.

## Evidence method: pinned executable fixtures

The new contracts have executable evidence: the pinned `openspec-cli-112` fixture proves them, while the retained `openspec-cli-111` proves the capability-boundary rejections (how an older CLI gets blocked is itself tested). The fixture method tightened at the same time: the worktree endpoint fixture pins a hermetic (self-contained) CLI runner, and Windows lock-release retries are bounded ([0baa17a0](https://github.com/jixoai/openspecui/commit/0baa17a0), [2c602a53](https://github.com/jixoai/openspecui/commit/2c602a53)). Across the 24 commits from 11.1.0 to 12.0.0, the v12 fixture matrix, the kernel findings transport, and the evidence panels landed together ([d782c98e](https://github.com/jixoai/openspecui/commit/d782c98e)); the compatibility gate and Agent registry switched over ([9e0b0383](https://github.com/jixoai/openspecui/commit/9e0b0383), release entry [d272b1f](https://github.com/jixoai/openspecui/commit/d272b1f)).

## Migration (breaking: the compatibility window)

The window switch is breaking: 1.10.x / 1.11.x are blocked by default. The lowest-friction path is a one-line CLI upgrade:

```bash
npm install -g @fission-ai/openspec@1.12
```

If an incompatible CLI executable is genuinely at hand, the mismatch dialog offers **Skip version check**. The bypass is held only by the current page runtime and clears on refresh/reopen. It creates no compatibility promise.
