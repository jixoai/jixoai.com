```text
14.0.0
```

OpenSpecUI v13 与 v14 发布，界面适配 OpenSpec CLI 1.13 与 1.14 两条线。两个版本的用户可见变化集中在三处：CLI 的各类提醒以可展开的摘要条呈现；任务证据携带源文件行号；Agent 工具支持从 40 个扩展到 50 个。协议层面的适配细节收在文末的折叠块中。

## 提醒按需展开

v13 起，改动详情页将 Apply 阶段的警告与待办顺序显示为一行摘要，点击展开完整内容；v14 起，`openspec status` 的咨询性警告加入同一呈现方式。例如 `.openspec.yaml` 存在未识别的键时，CLI 的提醒原文逐字显示：

```text
1 status warning — openspec status          ← 点击展开完整原文
2 apply warnings · next in build order: specs → design
```

两类提醒的覆盖范围如下：

1. 改动自身的警告：配置键写错、缺少 delta specs 等问题，以 CLI 原文显示，并指明正确的写法（v13 起为 Apply 输出，v14 起为 status 输出）
2. Apply 前的待办顺序：未完成的工件按依赖顺序列出（v13）

提醒不阻断操作，Apply 与归档按钮的可用性不受影响。摘要条默认收起，在窄屏与移动端不占用版面。

## 证据定位更精确

v14 起，apply 清单中的每个任务携带源文件路径与行号（tasks.md 的 1 起始行），任务证据可以直接定位到具体位置。同一版本中，规格页面的 requirement 与 scenario 标题改用 CLI `show --type spec` 输出的名称，与命令行结果保持一致，不再从 Markdown 结构推断。

## 扩展 Agent 工具支持

v14 的 Agent 注册表新增十个工具，总数从 40 到 50：

> amp · atomcode · codestudio · dsh · easycode · gigacode · grok · gsd · veai · warp

Bob Shell 更名为 IBM Bob，命令与目录不变。v13 期间注册表未新增工具，仅跟随上游调整路径（Kilo 的命令迁移到 `.kilo/command/`）。

## 升级

```bash
npm i -g @fission-ai/openspec@1.14
npx openspecui@latest
```

每个大版本对应一条 CLI 线：v14 对应 1.14，v13 对应 1.13，v12 对应 1.12。需要留在旧线时，使用对应版本的 OpenSpecUI（例如 `npx openspecui@13`）。检测到不兼容的 CLI 时界面会弹出对话框，其中「跳过版本检查」仅对当前页面生效，刷新后失效。

<details>
<summary>展开：v14 接入的六类 CLI 输出</summary>

- `openspec version --json`：版本与安装位置的机器可读输出
- `instructions apply`：每个任务的 `sourcePath` 与 `line`
- `list --archived` / `list --all`：区分已归档与进行中的改动
- `status`：顶层的咨询性警告
- `show --type spec --json`：规格的 requirement / scenario 名称
- store 场景下 `status` 的 `allowedEditRoots`：标明改动应落地的目录

</details>

<details>
<summary>展开：v13 的三个版本</summary>

1. **v13.0.0**：适配 OpenSpec CLI 1.13；Apply 提醒（警告与待办顺序）进入改动详情页
2. **v13.0.1**：适配 CLI 1.13.1；改动列表不再把命名空间目录显示为改动（`nested` 识别）；任务勾选兼容更多 Markdown 写法
3. **v13.0.2**：适配 CLI 1.13.2；任务进度的 glob 追踪证据；Kilo 命令路径迁移

</details>

<details>
<summary>展开：适配质量的验证方式</summary>

每次切换 CLI 线，测试矩阵以实际发布的 CLI 可执行文件运行：新版本验证契约成立，刚退役的版本（1.13.2）验证拒绝行为正确。v14 的适配经过 7 轮独立评审（规划 5 轮、实现终审 2 轮），记录见仓库的 [openspec 归档](https://github.com/jixoai/openspecui/tree/main/openspec/changes/archive/2026-10-02-target-openspec-cli-114-line)。

</details>
