OpenTray v0.21.1 发布了（2026-09-06，仓库的第一份 GitHub Release）。这一版的正事是发布自动化：每个发布版本自动切出一份 GitHub Release，jixoai.com 的版本 pill 从「v—」第一次显示 v0.21.1。create-opentray 0.21.0 的全新安装 404 同步修复，0.21.1 是 command families（按运行器家族组织的命令输入界面）第一个可安装的版本。

## 发布自动化：每个版本都有一份 GitHub Release

此前这个仓库经 changesets 发 npm 包，但**零 GitHub Releases**，想看某个版本的变更记录，GitHub 上没有对应页面；本站的版本 pill 长期显示「v—」，org blog 也链不到 release。[变更提案](https://github.com/jixoai/opentray/blob/main/openspec/changes/archive/2026-09-06-release-automation-and-copy/proposal.md)补上了管道：每个发布版本同时切出 GitHub Release（tag = 包版本，notes = changesets 生成的 changelog 节）；workflow_dispatch 允许为当前版本补切一份 release（bootstrap 路径）。opentray@0.21.1 就是走 bootstrap 路径切出的第一份。从下一个版本起，release notes 全自动。

## 背景：轻量工具值得系统级入口

OpenTray 的产品目标从来不止「显示一个托盘图标」。[AGENTS.md 的 Vision](https://github.com/jixoai/opentray/blob/main/AGENTS.md) 一句话讲完：给轻量工具一个系统级入口，**不必强迫用户引入 Electron 或整套桌面应用框架**。CLI 工具、AI skill 与本地守护进程，它们值得常驻状态面与点击入口，但为一个小图标引入上百 MB 的运行时不成立。

当前的答案是托盘优先的平台模型，四个本体的分工如下。

- `App`：调用方持有的运行时身份与隔离边界
- `Tray`：归属该 app 的单个桌面状态原子
- `Session`：托盘事件与变更的实时权威来源
- `Extension`：作用域限定在 app 与托盘上的原生能力原子

应用代码直接 `createTray()`，自行持有前台/后台生命周期（上一代公共 API 的 `Space`/`Surface` 本体已退役）。第一个应用不需要打包器，也不加载 Node addon。普通应用代码经公共 tray/session 协议与运行时对话：

```ts
import { createTray, type TrayIcon } from "opentray";

let tray;
tray = await createTray(
  {
    id: "com.example.first-app",
    icon: { "text-only": "OT" },
    menu: {
      items: [
        { title: "Quit", primaryEvent: true, onMenuClick: () => void tray.destroy() },
      ],
    },
  },
  { appId: "com.example.first-app", appName: "First App" },
);
```

工作区的所有包按固定版本一起发布：`opentray`（SDK + CLI）、`@opentray/spec`（协议契约）、`@opentray/packaging` 与四个 bundler 适配器（vite/tsdown/esbuild/webpack 同一 manifest 形状）、`@opentray/ext-webview` 及平台 WebView 动态库、`@opentray/ext-badge`，Lynx 扩展独立维护在 [jixoai/opentray-ext-lynx](https://github.com/jixoai/opentray-ext-lynx)。

## 一行命令，把现有命令变成托盘应用

已经有在本地服务 HTTP 的命令？`npx create-opentray` 把它包装成 OpenTray 托管的应用，三条进入路径都在 [create-app 指南](https://github.com/jixoai/opentray/blob/main/skills/opentray/references/create-app.md) 里。

```bash
npx create-opentray web      # 浏览器向导，交互式
npx create-opentray create --app-id com.example.build \
  --app-name "Build" --exec "npm run dev"   # 完全非交互
npx create-opentray skill    # 内置 AI skill，交给代理读
```

0.21.0 的 command families 把向导的命令输入收敛成单行输入组：家族选择前缀 + 命令体。npm（npx/pnpx/bunx/yarn dlx/nubx/deno run/vpx）、`go run`、`cargo install`、`uvx/pipx run`、`dnx` 每个家族渲染成只读命令面，点开结构化表单（runner、包名/模块/crate/工具 id、版本、参数）；确认后写回命令串，取消则整个输入作废。家族感知的 appId 推导给同一个包跨 runner 的稳定身份。

```text
npx @deepseek-ai/dsh@latest web   → web.dsh.npmjs
go run rsc.io/fortune@latest      → fortune.golang
cargo install ripgrep（rg）        → rg.rust
```

## 升级

```bash
npm i create-opentray@0.21.1   # 0.21.0 用户必升（旧版装不上）
npm i opentray@0.21.1          # SDK 同线
```

使用官方扩展时锁同一条协议线：`pnpm add opentray@stable-A-B @opentray/ext-webview@stable-A-B`（协议线 tag 由 `@opentray/spec` 发布，勿与 `latest` 混用）。
