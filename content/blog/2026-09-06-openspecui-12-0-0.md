OpenSpecUI 12.0.0 发布了（2026-09-04）。这一版的主要内容是一次完整的兼容窗口切换：适配 OpenSpec CLI 1.12 单系列，同时把 validate 的验证发现做成机器可读的一等输出。

## 背景：大版本跟随 CLI minor 线

OpenSpecUI 的大版本通常跟随 OpenSpec CLI 的 minor 线（[README 兼容表](https://github.com/jixoai/openspecui/blob/main/README.md)），从 6 月的 3.x 到 8 月的 11.x，每条历史线都留有对应的 legacy README（1.11 / 1.9 / 1.7 / 1.6 / 1.3 / 1.2 / 1.x / 0.16）。12 的窗口是**单系列**的：`>=1.12.0 <1.13.0`，稳定的 1.12.x 即当前推荐线；1.10.x / 1.11.x（那是 11 的窗口）与更老的线默认 blocked，预发布和 `>=1.13.0` 同样被挡。1.13 没有被预先认领。它发布时，是否准入由另行验证的结果决定（放宽 12.x 的窗口，或出一个新 major）。

## validate --report findings：机器可读的验证发现

过去要把验证结果接进 CI，只能解析人读的日志；现在 `validate --report findings` 直接输出机器可读的类型化发现，CI 可以只消费发现而不丢全量结论。findings-only 条目在**保留整轮 totals 与 exit codes** 的前提下单独交付；请求侧错误（`invalid_validation_report_request`）按同一套结构化诊断格式返回。这份输出是能力门控的：1.12 线的 CLI 才提供，老 CLI 会被明确拒绝。

```bash
openspec validate --report findings
```

契约本身在评审轮里被收紧：findings 的 argv owner 被门控、workflow fixtures 完成移植（[677cbe13](https://github.com/jixoai/openspecui/commit/677cbe13)）；发布前，证据面板统一到共享的 header 契约，验证发现被归因到所属的 change（[1aa9ce43](https://github.com/jixoai/openspecui/commit/1aa9ce43)、[13bb0e15](https://github.com/jixoai/openspecui/commit/13bb0e15)）。

## 合并冲突建议：一等 INFO 级

合并冲突的建议不再和失败混在一起。`Archive would refuse this delta` 与 `Could not check archive merge conflicts` 这两类 advisory 现在渲染为第一类的信息级（INFO），**不改变 validity 证据**；archive 前的合并冲突检查结果第一次有了自己的等级。

## Agent 交付新增 SourceCraft Code Assistant

SourceCraft Code Assistant 用户现在也能直接收到 OpenSpecUI 的 Agent 交付：skill 引用是自然语言的，命令落在 `.codeassistant/commands/opsx-<id>.md`，无需 IDE 重启，也没有迁移步骤。1.12 会话的 Agent 交付注册表因此再添一家（SourceCraft Code Assistant，`.codeassistant`）；生成器的基线同步到 1.12.0。

## 证据方法：版本锁定的可执行 fixtures

新契约有可执行的证据：版本锁定的 `openspec-cli-112` fixture 验证新契约成立，保留的 `openspec-cli-111` 验证能力边界的拒绝路径（老 CLI 被挡住时的行为也是被测的）。fixture 方法同时收严：worktree 端点 fixture 里锁定了自包含的 hermetic CLI runner（不依赖外部环境），Windows 锁释放的重试有界（[0baa17a0](https://github.com/jixoai/openspecui/commit/0baa17a0)、[2c602a53](https://github.com/jixoai/openspecui/commit/2c602a53)）。从 11.1.0 到 12.0.0 的 24 个提交里，v12 fixture 矩阵、内核 findings 传输与证据面板一次落地（[d782c98e](https://github.com/jixoai/openspecui/commit/d782c98e)），兼容门与 Agent 注册表完成切换（[9e0b0383](https://github.com/jixoai/openspecui/commit/9e0b0383)，发布条目见 [d272b1f](https://github.com/jixoai/openspecui/commit/d272b1f)）。

## 迁移（破坏性：兼容窗口）

窗口切换是破坏性的：1.10.x / 1.11.x 默认被挡。最低摩擦路径是一行升级 CLI：

```bash
npm install -g @fission-ai/openspec@1.12
```

如果手头确有不兼容的 CLI 可执行文件，mismatch 对话框提供 **Skip version check**。该旁路只在当前页面运行时内有效，刷新/重开即清，不构成兼容承诺。
