UniPty v0.2.0 发布了（GitHub Release 于 2026-08-20 切出）。这一版的主菜是 **shell-parser 生态**：两个可选的官方解析器包，把命令文本翻译成 UniPty 的结构化启动，全程不执行一个字节。至此第一阶段的 8 个公共包第一次以完整形态同时出现在 npm 上。

## 背景：一份契约，三条运行时

Node、Bun 与 Deno 各自暴露互不兼容的 PTY 底座，从安装模型、I/O 表示，到生命周期语义、原生部署约束，全都不同（这是 [v1 架构提案](https://github.com/jixoai/unipty/blob/main/openspec/changes/archive/2026-08-20-add-unipty-v1-pty-platform/proposal.md)开篇的原始动机）。UniPty 的赌注是把这些差异全部吸收到一份「小而诚实」的公共契约后面：Core 拥有一切可观察行为，开发者显式选择 Backend，支持声明由证据门控。

2026-08-20 当天，0.1.x 先行落地了核心契约与三条官方 Backend 路线（Node 走第三方 `node-pty`，Bun 走运行时原生的 `Bun.Terminal`，Deno 走自包含的 `@sigma/pty-ffi`）。0.2.0 补上的是 v1 架构预留的最后一个接缝：**可选的官方 Shell Parser 包**。Core 只收结构化 argv、永不执行命令文本，而迁移自字符串命令工具的消费者总得有人替他们把文本这关过掉。

支持声明是同一套诚实契约的另一翼：一个 runtime/platform 组合只有当公共 conformance 套件对**已安装的包产物**（pack 并装入隔离消费者，只经公共导出驱动）全量通过时才标记 `verified`；其余一律诚实地是 `declared-unverified` 或 `not-targeted`，失败留在 CI 诊断里、永不固化成永久性的 unsupported 声明（见 [conformance 文档](https://github.com/jixoai/unipty/blob/v0.2.0/README.md#conformance--compatibility-evidence)）。

## 命令文本 ≠ 命令：@unipty/shell-parser

Core 没有字符串命令重载，隐式 shell 正是它要消灭的那类事故；但从字符串命令工具迁移过来的消费者，此前只能手写「文本 → argv」的翻译。`@unipty/shell-parser` 补上了这层：[unbash](https://www.npmjs.com/package/unbash) 之上的同步薄包装，唯一的公共面是分类结果，unbash AST 永不外泄。翻译的目标就是 Core 的契约一览：`spawn(argv, options)` 同步且 argv 是结构化数据；`write()` 返回布尔 Readiness，饱和时整值拒绝并给出类型化的 `backpressure`；`close()` / `terminate()` 幂等且同步，不级联；`exited` 可重复 await，独立于流完成与关闭（[契约一览](https://github.com/jixoai/unipty/blob/v0.2.0/README.md#contract-at-a-glance)）。

```ts
import { parse } from "@unipty/shell-parser";

parse("git status --force");
// → { kind: "argv", argv: ["git", "status", "--force"] }

parse("ls *.txt | wc -l");
// → { kind: "script", language: "bash", source: "ls *.txt | wc -l" }

parse("echo 'unterminated");
// → { kind: "incomplete", diagnostics: [...] }
```

五分类 `argv | script | incomplete | unsupported | invalid` 是唯一的稳定边界。`argv` 意味着文本在词法上恰好是一条简单命令（引号与空参数保留），可以直接喂给 `unipty.spawn(argv)`；`script` 意味着文本带 shell 语义（管道与重定向，展开、替换与 glob，后台、赋值前缀……），必须由你显式接受指定的 shell 策略后才谈得上启动。可执行文件解析（PATH、内建，函数、别名）始终是你的决定，解析器永不为一个命令名主张进程启动等价性。

分类政策是刻意保守的：转义元字符（`echo \*`）与未加引号的括号字符（`[ -f x ]`）同样归入 `script`。walker 从原始词文本证明「字面性」，任何含糊都停留在 shell 请求一侧，绝不猜。见[包文档](https://github.com/jixoai/unipty/blob/v0.2.0/packages/shell-parser/README.md)。

## PowerShell 只认官方解析器：@unipty/powershell-parser

Bash 语义的猜测式解析搬到 PowerShell 上就是另一种事故。`@unipty/powershell-parser` 的语义权威只有一个：官方 `Parser.ParseInput` API，通过显式选择的 PowerShell host（默认 `pwsh`）调用。适配脚本以 `-EncodedCommand` 传输；你的文本以 base64 编码的 UTF-8 走 **stdin**，不经命令行插值，也不受 Windows 控制台代码页歧义影响。

```ts
import { parsePowershell } from "@unipty/powershell-parser";

await parsePowershell('dotnet build -c "My Config"');
// → { kind: "argv", argv: ["dotnet", "build", "-c", "My Config"] }
```

失败是类型化的三段：host 缺席 → `capability-unavailable`（绝不回落到 Bash 式解析）；host 启动但异常退出、返回未知结果 → `host-failure`（绝不静默降级成 `script`）；超出预算（默认 15 秒，`timeoutMs` 可配）→ `host-timeout`。

host 的选择也是显式的：`isPowershellHostAvailable()` 先探；`options.host` 可以指定其它可执行文件（例如 Windows PowerShell 5.1 的 `powershell`，它同样提供 `Parser.ParseInput`）。官方 `ParseError` 记录序列化为 `{ message, errorId, incomplete, range }`，带 UTF-16 偏移；标记为 `IncompleteInput` 的错误映射为 `incomplete`，其余归 `invalid`。见[包文档](https://github.com/jixoai/unipty/blob/v0.2.0/packages/powershell-parser/README.md)。

## 发布原子性：parser 包先行

一次发布 8 个包，顺序是刻意的：[release workflow](https://github.com/jixoai/unipty/blob/v0.2.0/.github/workflows/release.yml) 先发两个 parser 包，再发核心与 Backend。CI 注释写明了理由。parser 是最新的包名、最可能没配好 Trusted Publisher，任何鉴权失败必须发生在「已发布的核心/Backend 包造成不可逆的半截 release」之前。npm 时间戳可以核对：`@unipty/shell-parser@0.2.0` 于 11:00:13 上架，`unipty@0.2.0` 于 11:00:26 跟进，GitHub Release v0.2.0 于 11:01 切出。

- powershell-parser 文本传输改走 stdin 并强制严格 host 失败（[7f121ff](https://github.com/jixoai/unipty/commit/7f121ff)）

## 升级

无破坏性变更。parser 生态是纯新增包，Core / Backend / acquisition / helper / conformance 代码零改动（[变更提案](https://github.com/jixoai/unipty/blob/main/openspec/changes/archive/2026-08-20-add-shell-parser-ecosystem/proposal.md)的 Impact 原文）。升级即：

```bash
npm i unipty@0.2.0
# 可选：按需加装解析器
npm i @unipty/shell-parser@0.2.0 @unipty/powershell-parser@0.2.0
```
